Context:

Scrum team members need to estimate many user stories for implementation plan. So they need a tool to do that thing.

How to estimate:
The estimation would be in 2 stage for each user story, one is high level estimation (rough estimation), one is sprint plan estimation (detail estimation)
The estimation always based on 3 factors:
- Risk: Unclear Demand, Dependence on 3rd party, Uncertainty in the future
- Complexity: Efforts needed to develop a particular feature
- Repetition: Monotonous tasks without any risks and complexity

How the app server the estimation:
All members need to get a name, set an avatar or system will pick randomly.
A host will set the rule of the estimation room: type of estimation (t-shirt, fibonacci, modified Fibonacci, custom points).
A host will set the list of user stories before start the estimation session.
When the team start to estimate, they need to pick for 3 factors (on the scale of 10) before pick the point.
After all members done the estimation, they will show all their point card with the stat of 3 factors (the host will be the one take this action), if there is gap among members then we should restart the estimation until all members on the same page (same story point).
After the estimation is done for a user story, it will be in the history log with Risk, Complexity, Repetition stats.
When the team run through some user story, they would consider the history estimation as a baseline story point so they can consider to compare to pick quick estimation for all later stories.

Theme of the app:
- make it fun
- make the avatar fun and cute
- make it look like 8 bit game
